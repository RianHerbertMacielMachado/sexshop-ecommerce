⚙️ Serviço: API (Backend)

O "cérebro" da loja. Processa pedidos, gerencia usuários, fala com o banco de dados e com os sistemas de pagamento. Roda na porta 3001. Nunca visível diretamente pelos clientes.

🖥️ Serviço: Web (Frontend)

O que os clientes e o administrador veem. Feito em Next.js, carrega rápido e funciona bem em celular. Roda na porta 3000. Este é o endereço que você divulga.

🐘 Serviço: PostgreSQL

O banco de dados da loja. Guarda tudo: produtos, pedidos, clientes, configurações, cupons. Gerenciado automaticamente pelo Railway — você não precisa configurar nada além de criar.

Glossário — O que são essas palavras?

Entenda os termos técnicos antes de começar — leia isso primeiro!

💬
Se você nunca fez isso antes, leia com atenção. Você vai encontrar palavras como "API", "variável de ambiente", "token" e "webhook" ao longo do manual. Esta seção explica cada uma delas em linguagem simples.
🔑 API Key / Chave de API
Funciona como uma "senha de acesso" para serviços online. É um código longo e único que identifica você. Pense como um "crachá digital" — quem tiver esse crachá pode usar o serviço em seu nome.
🌍 Variável de Ambiente
É um lugar seguro para guardar senhas e configurações fora do código. Em vez de escrever sua senha diretamente no código (perigoso!), você coloca numa "variável" separada que só o servidor consegue ler.
🔔 Webhook
É um "aviso automático". Quando algo acontece num serviço (ex: pagamento confirmado no Stripe), ele envia uma mensagem para a sua loja automaticamente. Como uma campainha — o Stripe "aperta a campainha" da sua loja para dizer que o pagamento foi aprovado.
🎫 Token JWT
É uma "pulseira de festa" digital para usuários logados. Quando alguém faz login, recebe esse token. Em cada requisição, mostra o token para provar que está logado. JWT_SECRET é a chave para criar e verificar essas pulseiras.
🗄️ DATABASE_URL
É o "endereço completo com senha" do banco de dados. Contém o servidor, a porta, o usuário e a senha tudo numa só linha, separados por : e @. O Railway gera isso automaticamente para você.
🏗️ Deploy
É o processo de publicar uma versão do seu código na internet. Quando você "faz deploy", o código que estava só no seu PC passa a rodar num servidor que qualquer pessoa do mundo pode acessar.
🔒 HTTPS / SSL
O cadeado 🔒 que aparece na barra do navegador. Significa que a comunicação entre o visitante e a loja é criptografada (segura). O Railway configura isso automaticamente — você não precisa fazer nada.
📦 Seed (popular banco)
É um script que insere os dados iniciais no banco de dados. Pense como "plantar sementes" — você executa uma vez e ele cria o usuário administrador, categorias padrão e configurações básicas para a loja já poder ser usada.
🔐 Secret Key vs Public Key
Secret Key = chave privada. Fica só no servidor. Se vazar, alguém pode fazer cobranças em seu nome. Public Key = chave pública. Pode aparecer no código do navegador sem problema. Serve apenas para identificar, não para cobrar.
☁️ Cloud Name (Cloudinary)
É o nome único da sua "pasta" no Cloudinary. Aparece na URL de todas as imagens que você faz upload. Ex: se seu cloud name for loja123, as fotos ficam em res.cloudinary.com/loja123/image/upload/...
🧂 Senha de App (Gmail)
É uma senha de 16 letras que o Google gera para aplicativos terceiros usarem seu Gmail. Diferente da sua senha normal, ela só pode enviar e-mails — não consegue ler, excluir ou acessar sua conta. Muito mais seguro!
🚂 Railway
É o serviço de hospedagem onde sua loja vai rodar. Funciona como uma "locação de computador na nuvem". Você não precisa configurar servidor, sistema operacional ou banco de dados — o Railway cuida de tudo automaticamente.

Etapa 1 — Criar as Contas Necessárias

6 serviços, todos com plano gratuito — leva cerca de 15 minutos no total

💡
Dica de organização: Antes de começar, abra um bloco de notas (Notepad, Google Keep ou qualquer editor de texto) e vá colando as chaves que você vai obter. Você vai precisar delas todas na Etapa 8.
1

🐙 GitHub — github.com

GitHub é onde o código do projeto fica guardado. Pense nele como um "Google Drive para programadores". O Railway vai buscar o código diretamente daqui para publicar.

Acesse github.com e clique em "Sign up" (canto superior direito)

Ou clique no botão verde "Sign up for GitHub" no centro da página.

Informe seu e-mail, crie uma senha e escolha um nome de usuário

O nome de usuário é público e vai aparecer nos endereços dos repositórios. Ex: joaosilva

Confirme o e-mail clicando no link enviado pelo GitHub

Se não chegou, verifique a caixa de Spam.

2

🚂 Railway — railway.app

Railway é a plataforma onde a loja vai rodar 24 horas por dia. Oferece $5/mês de crédito gratuito — suficiente para lojas pequenas.

Acesse railway.app e clique em "Login" (canto superior direito)
Selecione "Login with GitHub"

Isso conecta automaticamente o Railway ao seu GitHub. Não crie uma conta separada — use sempre o login com GitHub.

Autorize o Railway a acessar sua conta GitHub quando pedido

Clique em "Authorize railway-app" na tela de autorização do GitHub.

3

☁️ Cloudinary — cloudinary.com

Cloudinary armazena e otimiza as imagens dos produtos. Quando você faz upload de uma foto pelo painel admin, ela vai para o Cloudinary e fica com um link permanente. O plano gratuito tem 25 GB.

Acesse cloudinary.com e clique no botão roxo "Sign Up For Free"
Preencha nome, e-mail e senha — ou use "Continue with Google"
Confirme o e-mail e acesse o Dashboard

Pronto. As credenciais já estarão visíveis no dashboard — vamos pegá-las na Etapa 2.

4

💳 Stripe — stripe.com/br

Stripe processa pagamentos com cartão de crédito. Você pode usar em modo de teste sem precisar de CNPJ ou documentação — ideal para configurar e testar antes de abrir a loja.

Acesse stripe.com/br e clique em "Comece agora"
Informe e-mail, nome completo, país (Brasil) e senha
Confirme o e-mail — você será redirecionado ao Dashboard do Stripe

Não precisa preencher informações bancárias agora — isso só é necessário quando for realmente receber pagamentos.

5

📱 Mercado Pago — mercadopago.com.br/developers

Mercado Pago processa pagamentos via PIX. Se você já tem uma conta Mercado Pago pessoal, pode usar a mesma. Caso contrário, crie uma agora.

Acesse mercadopago.com.br e crie uma conta ou faça login
Após logado, acesse mercadopago.com.br/developers/panel

Este é o painel de desenvolvedores onde ficam as chaves de API.

6

📧 Gmail — conta Google existente

Para envio de e-mails automáticos (confirmação de pedido, recuperação de senha, etc). Você vai usar sua conta Gmail normal, mas com uma "Senha de App" especial — não a sua senha do Gmail. Explicamos como obter isso na próxima etapa.

ℹ️
Não é necessário criar uma nova conta Google. Use qualquer conta Gmail que você já tenha. Se preferir, crie uma conta separada só para a loja (ex: minhasexshop@gmail.com).

💳 Stripe — 3 Chaves (para pagamento com cartão de crédito)

O Stripe é o sistema de pagamento com cartão. Ele tem dois "modos":

🧪 Modo TESTE (use agora)

As chaves começam com pk_test_ e sk_test_. Não movimenta dinheiro real. Use para configurar e testar a loja. É o que você deve usar agora.

💰 Modo PRODUÇÃO (depois)

As chaves começam com pk_live_ e sk_live_. Movimenta dinheiro real. Só ative quando a loja estiver pronta e você tiver verificado sua conta no Stripe.

Parte 2 — Criar o Webhook (o "aviso de pagamento confirmado")

🔔
Para que serve o webhook? Sem ele, quando um cliente paga, o Stripe recebe o dinheiro mas sua loja não fica sabendo que o pagamento foi aprovado. O webhook é a forma do Stripe avisar sua loja: "Ei, o pedido X foi pago!". Sem webhook, o pedido nunca muda para status "Pago".
⏳
Faça isso depois da Etapa 6. Você vai precisar da URL da sua API para criar o webhook. Complete a Etapa 6 primeiro, pegue a URL da API e volte aqui.
dashboard.stripe.com › Developers › Webhooks › Botão "Add endpoint"
Vá em Developers → Webhooks no menu

Mesma área onde você pegou as API keys, mas agora clique em "Webhooks" no menu lateral esquerdo.

Clique no botão "Add endpoint" (no canto superior direito da tela de Webhooks)
No campo "Endpoint URL", cole a URL da sua API com o caminho do webhook

O formato é sempre: https://SUA-URL-API.railway.app/api/payments/webhook/stripe

Exemplo de URL do webhook
https://SUA-API-AQUI.railway.app/api/payments/webhook/stripe

Substitua SUA-API-AQUI pelo domínio real da sua API (que você vai obter na Etapa 6).

Em "Select events" (selecionar eventos), escolha os 3 eventos abaixo

Uma caixa de seleção vai abrir. Há uma barra de pesquisa — pesquise cada um dos 3 nomes abaixo e marque a caixinha ao lado:

Pesquise e marque estes 3 eventos
checkout.session.completed
payment_intent.payment_failed
charge.refunded

Tradução: "sessão de checkout concluída", "intenção de pagamento falhou" e "reembolso realizado".

Clique em "Add endpoint" para criar e depois copie o "Signing secret"

📧 Gmail — Criar uma Senha de App (para enviar e-mails automáticos)

Quando um cliente faz um pedido, a loja envia um e-mail automático de confirmação. Para isso, você vai "emprestar" sua conta Gmail à loja, mas de forma segura — usando uma Senha de App especial, não sua senha normal.

✅ Senha de App

Uma senha de 16 letras criada especialmente para aplicativos. Só envia e-mails, não tem acesso a nada mais. Muito mais segura.

❌ Senha normal do Gmail

Nunca use sua senha normal! Ela daria acesso total à conta. O Google até bloqueia isso por segurança.

📋
Requisito obrigatório: Verificação em 2 etapas (2FA) ativa. O Google só permite criar Senhas de App se você tiver a verificação em 2 etapas ativada na sua conta. Se não tiver, o Passo 1 abaixo explica como ativar (leva 2 minutos).
Passo 1 — Verifique e ative a "Verificação em 2 etapas" (se ainda não tiver)
myaccount.google.com › Segurança › Como você faz login no Google › Verificação em duas etapas

Link direto: myaccount.google.com/security

Na seção "Como você faz login no Google", veja se a "Verificação em 2 etapas" está Ativada. Se não estiver, clique nela e siga os passos para ativar (confirma com seu celular por SMS ou app).

✅
Se já tiver ativado, pode pular direto para o Passo 2.

2

Adicione o domínio no Railway

serviço web › Settings › Networking › Custom Domain › Add Domain

Digite seu domínio (ex: www.minhasexshop.com.br) e clique em Add Domain. O Railway vai mostrar um registro DNS para você configurar.

3

Configure o DNS no seu registrador

O Railway mostrará um registro CNAME com o destino. Acesse o painel do seu registrador (onde comprou o domínio) e crie esse registro DNS:

TipoNomeValor
CNAMEwww(o destino fornecido pelo Railway)

A propagação do DNS pode levar de 5 minutos a 24 horas, mas geralmente é em menos de 1 hora.

4

HTTPS automático — nenhuma ação necessária

O Railway gera o certificado SSL automaticamente. O cadeado 🔒 vai aparecer sozinho assim que o DNS propagar.

5

Atualize a variável FRONTEND_URL no serviço api

Com o domínio configurado, atualize a variável FRONTEND_URL no serviço api para o novo domínio:

https://www.minhasexshop.com.br

O serviço api vai reiniciar automaticamente após a atualização.

Problemas Comuns e Como Resolver

Se algo der errado, encontre o seu problema aqui

🔍
Como ver os logs de erro no Railway: Clique no serviço com problema → aba Deployments → clique no deploy mais recente → botão View Logs. Leia as últimas linhas em vermelho para identificar o erro.
!

Deploy falhou — "Environment variable not found" ou "process.env.X is undefined"

Causa: Uma ou mais variáveis de ambiente obrigatórias não foram configuradas, ou foram colocadas no serviço errado.

Solução passo a passo:

  1. Nos logs, veja qual variável está faltando (ex: JWT_ACCESS_SECRET)
  2. Vá no serviço que falhou → aba Variables
  3. Verifique se a variável existe e está no serviço correto
  4. Se não existir, adicione com o valor correto
  5. Após adicionar, clique em Redeploy no menu do serviço
!

Loja abre mas não carrega produtos — "Network Error" ou tela em branco

Causa: A variável NEXT_PUBLIC_API_URL está incorreta ou faltando no serviço web.

  1. Vá ao serviço web → Variables → verifique NEXT_PUBLIC_API_URL
  2. Confirme que o valor começa com https:// e não tem barra no final
  3. Confirme que é a URL do serviço api (não do web)
  4. Vá ao serviço api → Variables → confirme que FRONTEND_URL aponta para a URL do serviço web
  5. Tente acessar a URL da API diretamente no navegador: https://SUA-API.railway.app/api/products — deve retornar JSON
!

Imagens de produtos não aparecem ou não sobem

Causa: Uma das 3 credenciais do Cloudinary está incorreta.

  1. Acesse o dashboard do Cloudinary → verifique as 3 credenciais
  2. No Railway, serviço api → Variables → confirme CLOUDINARY_CLOUD_NAME, CLOUDINARY_API_KEY e CLOUDINARY_API_SECRET
  3. O erro mais comum é o CLOUDINARY_API_SECRET — certifique-se de ter clicado em "Reveal" e copiado o valor real, não apenas os pontos ••••••••
!

E-mails não chegam aos clientes

Causa: SMTP configurado incorretamente, ou usando a senha normal do Gmail em vez da Senha de App.

  1. Confirme que SMTP_PASS é a Senha de App de 16 caracteres, não sua senha normal do Gmail
  2. A senha de app não tem espaços — se gerou abcd efgh ijkl mnop, use abcdefghijklmnop
  3. Confirme que SMTP_USER é o mesmo e-mail da conta que gerou a Senha de App
  4. Verifique se a Verificação em 2 etapas está ativa na conta Google
  5. Se o e-mail não existe mais, gere uma nova Senha de App em myaccount.google.com/apppasswords
!

Pagamento com cartão falha — Erro 500 ou "Payment failed"

Causa: Chaves do Stripe incorretas ou webhook não configurado.

  1. Confirme que está usando as chaves de teste (com sk_test_ e pk_test_) para testar
  2. Não misture chaves de teste e produção — ambas precisam ser do mesmo modo
  3. Verifique se o webhook no Stripe está com a URL correta (etapa 2, parte 2)
  4. Para testar cartão, use sempre: número 4242 4242 4242 4242, qualquer data futura e qualquer CVV
!

Pedido não muda para "Pago" após pagamento bem-sucedido

Causa: Webhook do Stripe não está configurado corretamente ou o STRIPE_WEBHOOK_SECRET está errado.

  1. Acesse Stripe Dashboard → Developers → Webhooks → clique no endpoint criado
  2. Veja a seção "Recent deliveries" — deve mostrar tentativas de envio
  3. Se aparecer erro 401, o STRIPE_WEBHOOK_SECRET está errado — copie novamente do Stripe
  4. Se não aparecer nenhuma entrega, a URL do webhook está errada — confirme que termina em /api/payments/webhook/stripe
!

Erro ao executar npx prisma db push no shell do Railway

Causa: A DATABASE_URL está incorreta ou o banco PostgreSQL não está rodando.

  1. Confirme que o serviço PostgreSQL está com status Active (verde) no painel
  2. Vá ao serviço PostgreSQL → Variables → copie a DATABASE_URL novamente
  3. Atualize a variável no serviço api e aguarde o redeploy
  4. Tente executar o comando novamente no Shell
!

Railway mostra aviso de "crédito esgotado"

Causa: O plano gratuito do Railway oferece $5/mês de crédito, que pode acabar com uso intenso.

  1. Monitore o uso em Settings → Usage no dashboard do Railway
  2. Para uma loja pequena/média, $5 cobrem o mês inteiro
  3. Se precisar de mais, o plano Hobby custa $5/mês fixo + consumo — mais previsível
  4. Para reduzir custos: configure sleep nos serviços quando estiver testando
