⚙️ Serviço: API (Backend)

Node.js + Express + Prisma rodando na porta 3001. Responsável por toda a lógica de negócio, pagamentos e banco de dados.

🖥️ Serviço: Web (Frontend)

Next.js 14 rodando na porta 3000. Interface da loja e painel admin que o cliente e administrador veem.

🐘 Serviço: PostgreSQL

Banco de dados gerenciado pelo próprio Railway. Armazena produtos, pedidos, usuários e todas as configurações.

☁️ Serviços Externos

Cloudinary (imagens), Stripe (cartão), Mercado Pago (PIX) e SMTP (e-mails). Todos gratuitos para começar.

👤

Etapa 1 — Criar Contas Necessárias

Você vai precisar de contas em 6 serviços. Todos têm plano gratuito.

💡
Dica: Use o mesmo e-mail em todos os serviços para facilitar o gerenciamento.
1

GitHub — github.com

Onde o código do projeto ficará armazenado. O Railway vai buscar o código diretamente daqui.

Clique em "Sign up", informe e-mail, senha e nome de usuário. Confirme o e-mail.

2

Railway — railway.app

Plataforma onde a loja vai rodar. Clique em "Login" e escolha "Login with GitHub" — isso já conecta as duas contas automaticamente.

3

Cloudinary — cloudinary.com

Armazena as imagens dos produtos. Clique em "Sign Up For Free". O plano gratuito tem 25 GB de armazenamento — mais do que suficiente para começar.

4

Stripe — stripe.com/br

Processa pagamentos com cartão de crédito. Clique em "Comece agora". Você pode usar em modo de teste sem precisar de CNPJ inicialmente.

5

Mercado Pago — mercadopago.com.br/developers

Processa pagamentos via PIX. Acesse o portal de desenvolvedores, faça login com sua conta Mercado Pago (ou crie uma) e acesse o painel de integrações.

6

Gmail (SMTP) — conta Google existente

Para envio de e-mails transacionais. Você vai usar sua conta Gmail com uma "Senha de App" — explicado na próxima etapa.

🔑

Etapa 2 — Obter Credenciais

Anote todas as chaves em um bloco de notas antes de continuar

🚨
NUNCA compartilhe estas chaves! Não coloque no GitHub, não envie por WhatsApp. Quem tiver estas chaves pode cobrar em seu nome.
☁️ Cloudinary — Chaves de API
1

Acesse o Dashboard

Após fazer login, você já estará no Dashboard principal. No topo da página aparece um quadro com suas credenciais.

2

Anote as 3 informações

Você precisará de:

  • Cloud Name — ex: dxyz123abc
  • API Key — ex: 123456789012345
  • API Secret — clique em "Reveal" para ver
💳 Stripe — Chaves de API
1

Acesse Developers → API Keys

No painel do Stripe, clique em Developers no menu superior, depois em API Keys.

2

Copie as chaves

Anote:

  • Publishable key — começa com pk_test_
  • Secret key — clique em "Reveal" — começa com sk_test_
3

Criar Webhook

Vá em Developers → Webhooks → Add endpoint. No campo URL, coloque:
https://SUA-API-URL.railway.app/api/payments/webhook/stripe

Em eventos, selecione: checkout.session.completed, payment_intent.payment_failed, charge.refunded. Clique em "Add endpoint" e copie o Signing secret (whsec_...).

📱 Mercado Pago — Access Token
1

Acesse o Portal de Desenvolvedores

Vá em mercadopago.com.br/developers/panel e faça login.

2

Crie um Aplicativo

Clique em "Criar aplicativo", dê um nome (ex: "MinhaSexShop"), selecione Pagamentos online e clique em Criar.

3

Copie as credenciais

Na aba Credenciais de teste, anote o Access Token (começa com TEST-). Para produção real, use a aba Credenciais de produção.

📧 Gmail — Senha de App para SMTP
1

Ative a verificação em 2 etapas

Acesse myaccount.google.com/security e ative a Verificação em duas etapas se ainda não tiver.

2

Gere a Senha de App

Na mesma página de segurança, procure por "Senhas de app" (pode precisar buscar). Clique, escolha Outro (nome personalizado), digite "SexShop" e clique em Gerar.

Anote a senha gerada (16 caracteres sem espaços). Essa senha só aparece uma vez.

💡
Suas configurações SMTP serão:
Host: smtp.gmail.com | Porta: 587 | Usuário: seu@gmail.com | Senha: a senha de 16 dígitos gerada
🐙

Etapa 3 — Subir o Código para o GitHub

Com Node.js e Git instalados no seu PC

1

Crie o repositório no GitHub

Acesse github.com/new. Preencha:

  • Repository name: sexshop-ecommerce
  • Visibility: Private (recomendado)
  • ⚠️ NÃO marque "Add a README file"

Clique em "Create repository". Copie a URL que aparece (ex: https://github.com/usuario/sexshop-ecommerce.git).

2

Abra o terminal na pasta do projeto

No VS Code, pressione Ctrl + ` (acento grave). O terminal abrirá já dentro da pasta do projeto.

3

Execute os comandos Git

Cole e execute um por um:

terminal 
git init
git add .
git commit -m "feat: initial project setup"
git branch -M main
git remote add origin https://github.com/SEU_USUARIO/sexshop-ecommerce.git
git push -u origin main
⚠️
Substitua SEU_USUARIO pelo seu nome de usuário do GitHub.
4

Confirme o envio

Acesse github.com/SEU_USUARIO/sexshop-ecommerce no navegador. Você deve ver todos os arquivos do projeto listados.

🚂

Etapa 4 — Criar Projeto no Railway

Conectando o Railway ao seu repositório GitHub

1

Acesse o Railway

Vá em railway.app/dashboard e faça login com GitHub.

2

Crie um novo projeto

Clique no botão "New Project" (botão roxo no canto superior direito).

3

Escolha "Deploy from GitHub repo"

Selecione essa opção, autorize o Railway a acessar seu GitHub se pedido, e então selecione o repositório sexshop-ecommerce.

4

Aguarde a detecção automática

O Railway vai detectar o arquivo railway.toml e reconhecer que são dois serviços (api e web). Clique em "Deploy Now".

💡
O primeiro deploy vai falhar — isso é normal! Ainda precisamos configurar o banco de dados e as variáveis de ambiente. Continue seguindo o manual.
🐘

Etapa 5 — Adicionar Banco PostgreSQL

O Railway oferece PostgreSQL gerenciado gratuitamente

1

No painel do projeto, clique em "New"

Dentro do seu projeto no Railway, clique no botão "+ New" ou "New Service".

2

Selecione "Database → PostgreSQL"

Clique em Database e depois em PostgreSQL. O Railway criará o banco automaticamente em segundos.

3

Copie a DATABASE_URL

Clique no serviço PostgreSQL criado, vá na aba "Variables" e copie o valor da variável DATABASE_URL. Ela se parece com:

DATABASE_URL
postgresql://postgres:SenhaGerada@containers-us-west-XX.railway.app:PORTA/railway

Guarde essa URL — você vai usá-la na próxima etapa.

⚙️

Etapa 6 — Configurar o Serviço da API

Apontando o Railway para o código do backend

1

Clique no serviço "api" no painel

Você verá os serviços criados automaticamente pelo railway.toml. Clique no serviço chamado api.

2

Verifique as configurações de build

Na aba Settings, confirme que:

  • Root Directory: apps/api
  • Build Command: npm run build
  • Start Command: npm run start
3

Gere um domínio público para a API

Na aba Settings, procure por "Networking" ou "Public Networking" e clique em "Generate Domain". Anote a URL gerada — você vai precisar dela para configurar o frontend.

Ficará algo como: api-sexshop-production.up.railway.app

🖥️

Etapa 7 — Configurar o Serviço do Frontend

Apontando o Railway para o código do Next.js

1

Clique no serviço "web"

De volta ao painel do projeto, clique no serviço chamado web.

2

Confirme as configurações

Na aba Settings, verifique:

  • Root Directory: apps/web
  • Build Command: npm run build
  • Start Command: npm run start
3

Gere o domínio do frontend

Também em Settings → Networking → Generate Domain. Este será o endereço da sua loja. Anote também.

Ficará algo como: sexshop-production.up.railway.app

Abra o terminal no seu PC e rode estes comandos — cada um gera uma chave aleatória segura:

Etapa 9 — Inicializar o Banco de Dados

Criar as tabelas e popular com dados iniciais

⚠️
Faça isso apenas uma vez, após configurar todas as variáveis de ambiente. Rodar o seed mais de uma vez pode duplicar dados.
1

Aguarde a API fazer deploy com sucesso

No Railway, clique no serviço api e verifique na aba Deployments se o status está como ✅ Success. Se ainda estiver falhando, verifique se todas as variáveis foram salvas corretamente.

2

Abra o terminal do serviço api no Railway

Na página do serviço api, clique na aba "Shell" ou procure o botão "Open Terminal". Isso abre um terminal direto no container da API no Railway.

3

Execute as migrações do banco

railway shell (serviço api) 
npx prisma db push

Isso cria todas as tabelas no PostgreSQL com base no schema.prisma.

4

Execute o seed (dados iniciais)

railway shell (serviço api) 
npx ts-node prisma/seed.ts

Isso cria o usuário admin, configurações da loja, categorias e métodos de pagamento padrão.

5

Anote as credenciais criadas

O seed vai exibir no terminal as credenciais do admin:

saída esperada
✅ Admin criado: admin@sexshop.com / Admin@123456
✅ Configurações da loja criadas
✅ Categorias padrão criadas
✅ Zonas de frete criadas
✅ Seed concluído!
⚠️
Troque a senha do admin imediatamente após o primeiro acesso em /conta/dados.
🌐

Etapa 10 — Domínio Personalizado (Opcional)

Configure um domínio próprio como www.minhaloja.com.br

💡
Não é obrigatório. Seu site já funcionará com o domínio gratuito do Railway (*.up.railway.app). Configure o domínio personalizado quando quiser.
1

Compre um domínio

Recomendamos registro.br para domínios .com.br ou namecheap.com para domínios .com internacionais.

2

Adicione o domínio no Railway

No serviço web, vá em Settings → Networking → Custom Domain. Digite seu domínio (ex: www.minhasexshop.com.br) e clique em Add Domain.

3

Configure o DNS

O Railway vai mostrar um registro CNAME para você configurar no painel do seu registrador de domínio. Adicione o registro apontando para o endereço fornecido pelo Railway.

Pode levar até 24h para propagar, mas geralmente é em menos de 1 hora.

4

HTTPS automático

O Railway gera o certificado SSL automaticamente. Não precisa fazer nada — o cadeado 🔒 vai aparecer sozinho.

5

Atualize a variável FRONTEND_URL

No serviço api, atualize a variável FRONTEND_URL para o seu domínio personalizado. Isso é importante para o CORS funcionar corretamente.

Problemas Comuns e Soluções

Se algo der errado, verifique aqui primeiro

!

Deploy falhou — "Environment variable not found"

Causa: Alguma variável obrigatória não foi configurada.

Solução: Vá no serviço que falhou → aba Variables → compare com a tabela da Etapa 8 e adicione as que estão faltando. Depois clique em Redeploy.

!

Frontend abre mas não carrega dados — "Network Error"

Causa: A variável NEXT_PUBLIC_API_URL está incorreta ou a API está fora do ar.

Solução: Verifique se a URL da API está correta (sem barra no final), se o serviço api está com status Success, e se a variável FRONTEND_URL na api corresponde à URL do frontend.

!

Imagens não aparecem ou não sobem

Causa: Credenciais do Cloudinary incorretas.

Solução: Verifique as três variáveis Cloudinary no serviço api. O CLOUDINARY_API_SECRET precisa ser revelado clicando em "Reveal" no dashboard do Cloudinary.

!

E-mails não chegam

Causa: SMTP mal configurado ou usando a senha da conta Google em vez da Senha de App.

Solução: Certifique-se de que SMTP_PASS é a Senha de App de 16 caracteres gerada no Google, não a sua senha normal do Gmail.

!

Erro 500 ao tentar pagar

Causa: Chaves do Stripe ou Mercado Pago inválidas ou webhook não configurado.

Solução: Confirme que está usando as chaves de teste (começam com sk_test_ e pk_test_) para testar, e as de produção apenas quando for abrir a loja de verdade. Verifique também o webhook do Stripe.

!

Railway cobra uso excessivo

Causa: O plano gratuito do Railway tem $5/mês de crédito.

Solução: Monitore o uso em Settings → Usage. Para uma loja pequena, os $5 gratuitos cobrem bastante. Quando crescer, o plano Hobby custa $20/mês.

🎉
Precisa de mais ajuda? Volte ao Claude e descreva exatamente qual erro está aparecendo — cole a mensagem de erro completa que aparece nos logs do Railway (serviço → aba Deployments → clique no deploy → View Logs).
